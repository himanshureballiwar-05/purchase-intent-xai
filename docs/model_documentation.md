# Model Documentation

*(Numbers in this file are described qualitatively; exact, always-current numbers are in `docs/model_card.md`,
which is regenerated by every training run.)*

## 1. Problem
Given a browsing session (17 behavioural fields), predict `Converted` (1 = purchase). Only ~15.7% of sessions convert.

## 2. Data
`dataset/ecommerce_sessions.csv` - 12,000 sessions, no missing values, no duplicates. Schema in `dataset/data_dictionary.csv`.
Stratified 80/20 split, fixed seed (42): 9,600 train / 2,400 test.

## 3. Pipeline
`BehaviourFeatures` -> `ColumnTransformer` -> optional `SMOTE` -> classifier (imbalanced-learn `Pipeline`).

| Group | Columns | Treatment |
|---|---|---|
| Skewed numerics | page counts, durations, `PageValues`, engineered totals | `log1p` + `RobustScaler` |
| Bounded numerics | `BounceRates`, `ExitRates`, `SpecialDay`, `ProductPageShare` | `RobustScaler` |
| Categoricals (incl. 4 integer-coded IDs) | `Month`, `VisitorType`, `OperatingSystems`, `Browser`, `Region`, `TrafficType` | `OneHotEncoder(handle_unknown="ignore")` |
| Flags | `Weekend`, `IsReturning` | passthrough |

CatBoost and LightGBM can handle categoricals natively, but all six models use the same one-hot pipeline so that the
comparison is controlled and the SHAP code is identical for every model.

## 4. Handling imbalance (three strategies benchmarked)
1. **SMOTE** inside the pipeline (training folds only).
2. **Class weights** (`class_weight`, `scale_pos_weight`, `auto_class_weights`).
3. **None + threshold tuning.**

PR-AUC is threshold-free, so strategies and models are ranked on it; recall/precision at 0.5 are reported but not used for ranking.

## 5. Model selection
- 6 models x 3 strategies, 5-fold stratified CV on the training set.
- Top-2 configurations tuned with `RandomizedSearchCV` (3-fold, scoring = PR-AUC); tuned result kept only if it beats the default in 5-fold CV.
- Best configuration by CV PR-AUC is refit on all training data.
- The **test set is used once**, for the final report.

## 6. Decision threshold
Acting on a session costs `c`; a saved purchase is worth `V`; the nudge works with probability `s`. Flagging is worthwhile
when `P(buy) * V * s > c`, i.e. above `c / (V * s)`. The threshold maximising expected net value on **out-of-fold training
predictions** is used (assumptions in `config.yaml -> business`; they are illustrative, not measured).

## 7. The PageValues question (leakage review)
- In this data 100% of buyers have `PageValues > 0` (vs about a third of non-buyers).
- `PageValues` is the most predictive feature by a wide margin; without it, PR-AUC falls from ~0.85 to ~0.53 (see `reports/ablation_page_values.json`).
- Decision: **keep it by default** (the model is intended for late-session scoring) but expose `features.use_page_values`
  so an early-scoring variant can be trained, and report the cost transparently.

## 8. Explainability
- **SHAP**: `TreeExplainer` for tree models, `LinearExplainer` for logistic regression. One-hot columns are summed back into
  their parent feature so explanations read as "Month", not "Month_Nov".
- **LIME**: tabular explainer on the encoded features, used as a second opinion.
- Explanations describe the model, not causal effects.

## 9. Reproducibility
Fixed seed, pinned `requirements.txt`, config in YAML, all runs logged to MLflow (`mlflow ui`), artifacts + metadata
(`models/metadata.json`) record versions, threshold and metrics.
